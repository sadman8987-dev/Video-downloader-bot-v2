# Video Downloader Bot V2

بوت Telegram مستقل لتنزيل الوسائط من الروابط العامة التي تدعمها أدوات الاستخراج، مع إرسال الملف داخل المحادثة.

## المزايا
- اختيار فيديو أو MP3.
- جودات الفيديو: 360p و480p و720p و1080p أو أفضل جودة متاحة.
- محرك محلي أساسي مبني على yt-dlp.
- محاولات YouTube متدرجة، مع إعداد PO Token اختياري وملف Cookies يضيفه المشغّل بنفسه عند الحاجة.
- gallery-dl كمسار احتياطي لبعض روابط Instagram.
- محرك تنزيل خارجي اختياري؛ عند تعطله يعود البوت تلقائيًا إلى yt-dlp المحلي.
- إعادة محاولة رفع Telegram عند أخطاء الشبكة أو الخادم المؤقتة دون إعادة تنزيل الملف.
- Redis اختياري لحفظ الاختيارات وأقفال المستخدمين بين نسخ الخدمة.
- FFmpeg وaria2 اختياريان بحسب إعداد التشغيل.

## التشغيل على Railway
1. اربط مستودع GitHub بخدمة Worker مستقلة.
2. استخدم Dockerfile الموجود في المستودع.
3. أضف BOT_TOKEN من Telegram BotFather إلى Railway Variables.
4. اترك محرك التنزيل الخارجي غير مضبوط إذا لم تكن لديك خدمة API متاحة؛ التنزيل المحلي يعمل بدونه.
5. REDIS_URL اختياري، وكذلك SENTRY_DSN وBGUTIL_POT_BASE_URL.
6. لا تضع أي أسرار أو ملفات Cookies داخل GitHub.

## متغيرات البيئة
راجع .env.example. الإعدادات الأساسية:
- BOT_TOKEN: مطلوب.
- MAX_FILE_MB: الحد الأقصى للتنزيل (افتراضي 100).
- TELEGRAM_UPLOAD_LIMIT_MB: سقف الرفع السحابي الافتراضي 49MB.
- MAX_DURATION_SECONDS: الحد الأقصى للمدة (افتراضي 1800 ثانية).
- DOWNLOAD_TIMEOUT_SECONDS: مهلة التنزيل.
- MAX_CONCURRENT_DOWNLOADS: عدد التنزيلات المتزامنة.
- DOWNLOAD_ENGINE_API_URL و DOWNLOAD_ENGINE_API_KEY: اختياريان لخدمة تنزيل خارجية.
- YOUTUBE_COOKIES_BASE64: اختياري، يضيفه المشغّل فقط عند الحاجة وبصيغة Netscape، ولا يُطلب من المستخدمين في كل عملية.

## حدود مهمة
حد رفع Telegram Bot API السحابي المستخدم هنا مضبوط افتراضيًا على 49MB. رفع MAX_FILE_MB وحده لا يرفع سقف Telegram؛ الملفات الأكبر تحتاج إعداد Telegram Local Bot API Server منفصلًا ومتوافقًا.
قد تمنع المنصات التنزيل أو تتطلب تحققًا/تسجيل دخول أو تقيّد بعض الروابط. لا يدعم البوت المحتوى الخاص أو المحمي بـ DRM ولا يتجاوز أنظمة الدخول. نزّل فقط المحتوى الذي تملك حق تنزيله.

## الاختبارات
تشغيل اختبارات المصدر:
`python -m unittest discover -s tests -v`

يتم فحص بناء Docker عبر GitHub Actions عند دفع التغييرات إلى الفرع الرئيسي، كما توجد مهام فحص اعتماديات وأمان في workflows.

## ملاحظات النشر
التعديلات على فرع إعادة البناء لا تغيّر خدمة Railway المتصلة بفرع main تلقائيًا. راجع نجاح الاختبارات والبناء أولًا، ثم ادمج الفرع وانشره في Railway بعد التحقق من الإعدادات.
